# Personal Kakeibo

iOS・iPadOS 17以上の個人用家計簿。SwiftUI、SwiftData、Swift Chartsを使用します。

入力、履歴の編集・確認付き削除、ジャンル管理、月別集計、12か月の推移、月間予算、CSV出力、JSONバックアップ・復元プレビューを実装しています。初期ジャンルは自動作成されます。日付・集計は日本時間・グレゴリオ暦です。

## 入力・予算・リマインダー

- ジャンルは3列のボタンで選択します。入力画面で長押しすると収入・支出それぞれの起動時の初期ジャンルになり、星で表示されます。
- テンキーの「00」で0を2桁追加できます。金額表示の右側の丸付き×ボタンで金額だけを全消去します。「⌫」は1桁削除です。メモ入力中に画面を下へスワイプするとキーボードを隠せます。入力・編集画面の日付から開くカレンダーには、収支のある日にドットを表示します。
- 設定 → ジャンル別の日額・月額予算で、食費などの上限を設定します。空欄で解除できます。保存・編集・削除の後に、その取引の日付・ジャンルの残額を画面で表示します。予算は毎日・毎月リセットされ、超過は負数です。
- リマインダーで毎日・毎週・毎月の収支予定を登録できます。期日分を確認して記録するか、その回だけスキップします。毎月の指定日が存在しない月は月末になります。無効化で予定の表示を休止できます。
- 予算・繰り返し収支ごとに「リマインドする」を選べます。予算は項目ごとに1日分の金額を個別通知します。日額設定を優先し、月額だけの場合は当月の日数で割り、1円未満を切り捨てます。繰り返し収支の確認通知は別にまとめます。初期時刻は7:00・12:00・18:00、最大3枠で変更・停止できます。月額の日割りは起動・復帰時に再計算するため、未起動で月をまたぐと次の起動まで前回の概算を通知します。通知から最新の残額と未記録予定を開けます。

集計・履歴の年月表示を押すとカレンダーが開き、年と月を選択できます。繰り返し収支は設定一覧の削除ボタンから削除できます。処理済み状態も削除し、記録済みの収支は残します。

初期ジャンル・通知時刻・通知許可は端末ごとの設定です。ジャンル別予算、繰り返し予定、処理済み状態は家計データに保存し、JSONバックアップにも含めます。従来のv1 JSONも読み込めます。既存ストアからは追加エンティティの軽量移行を行います。Appleのリマインダーアプリとの連携はありません。

## 開く・実行する

`PersonalKakeibo.xcodeproj`をXcode 26.3で開き、PersonalKakeiboスキームを選びます。Simulatorで実行するか、Signing & Capabilitiesで自分のTeamと実際のBundle IDを設定して実機で実行してください。標準のプロジェクトは端末内保存で、`com.example.PersonalKakeibo`は仮の識別子です。

プロジェクトを再生成する場合は、XcodeGenを用いて `xcodegen generate` を実行します。設定元は `project.yml` です。

## iCloud構成

実際に登録した識別子を指定して実行してください。値は自分のApple Developerアカウントのものに置き換えます。

```sh
python3 scripts/configure_cloud.py --team YOURTEAMID --bundle your.registered.bundle --container iCloud.your.registered.container
xcodegen generate --spec project-cloud.yml
```

生成される構成にはCloudKit、Remote notifications、development用のpush entitlementを含みます。XcodeでProvisioning ProfileとiCloud Containerの登録を確認してください。CloudKitの有効化を事前に省略したビルドで同期は行いません。設定したCloudKitコンテナの初期化に失敗した場合、空の保存領域への切替や既存データの削除は行いません。

同じApple AccountのiPhone・iPadで同期を確認する手順は [実機確認手順](docs/device-validation.md) にあります。署名・実際のContainer・2台の端末による同期確認は未実施です。

## テスト

Xcode 26.3 / Swift 6.2.4で次を実行します。

```sh
CLANG_MODULE_CACHE_PATH=/tmp/kakeibo-clang-cache SWIFTPM_MODULECACHE_OVERRIDE=/tmp/kakeibo-swift-cache swift test --scratch-path /tmp/personal-kakeibo-build --disable-sandbox
```

アプリと Widget の署名なし iOS Simulator ビルドは次で確認します。GitHub Actions も同じ手順を実行します。この結果は署名・実機・CloudKit・UI テストの合格を意味しません。

```sh
xcodegen generate
xcodebuild build -project PersonalKakeibo.xcodeproj -scheme PersonalKakeibo -destination 'generic/platform=iOS Simulator' CODE_SIGNING_ALLOWED=NO
```

DomainとApplicationをSwift Packageとして分離し、保存・復元・ViewModelのテストではSwiftDataのテスト用ストアと通知サービスの代替を使用します。入力、予算、繰り返し予定、口座・カード、契約の支払確認、返金、実質コスト、旧取込履歴付きデータの保持、旧スキーマ・旧JSONからの移行、保存失敗時のrollbackを確認しています。

## 入力画面と保存済みデータ

金額を右寄せ表示し、保存ボタンをタブバー上に固定し、横幅いっぱい・高さ48pt（文字サイズに応じて拡大）にしています。入力画面のタイトルはコンパクトに表示し、日付・口座・メモ・節約可能をまとめています。「節約可能」は取引ごとに保存され、履歴で識別・絞り込み・編集できます。成功後はフラグをオフ、ジャンルを設定済みの初期ジャンルへ戻します。失敗時は入力を維持します。旧記録のフラグはfalseです。

DB v3は節約フラグとLifeCost取込履歴を追加し、v1/v2から軽量移行します。JSON v3にはフラグ・取込履歴・カテゴリ対応を保存し、旧JSON v1/v2も読めます。CSVにはisSavingsEligible列を追加します。

旧LifeCostの予定取込履歴は保持します。旧形式の予定は支払確認まで実績・予算消費に加えず、同一予定の二重登録を防ぎます。

## はじめ方と管理

利用者の記録がない端末では、最初に「新しい家計簿を始める」を表示します。「収支を記録する」は入力タブへ、「サブスクリプションを追加」は新規契約画面へ、「所有物を追加」は新規所有物画面へ進みます。「後で始める」を選ぶと通常画面になります。案内を終えた状態は端末ごとに保存します。初期ジャンルだけでは利用開始済みとみなしません。

画面下部は「入力・履歴・ホーム・管理・設定」の5タブです。「管理」から、口座・カード・振替、支払予定、契約・サブスクリプション・保険、所有物・修理費、リマインダーへ進めます。設定は独立した「設定」タブから開きます。管理内の各画面から戻ると管理画面へ戻ります。通知を押すと管理内のリマインダーを直接開きます。

## 統合家計簿

案内を終えた後は「入力」が通常の起動時画面です。「ホーム」では利用日基準の実収支と、契約・所有物から計算する月別の実質生活コストを切り替えます。管理機能は「管理」から開きます。

口座は開始日と開始残高を設定します。開始日前の取引は残高に含めず、開始日以後の口座未指定取引があるとホームに未確定の注意を表示します。カード利用は利用日の支出とカード未払額に、引落は引落日の預金・カード残高に反映します。引落・振替は収支に再計上しません。返金は元の支出に紐付け、返金月の支出を減らします。

契約の支払間隔は任意の日・週・月・年数で指定できます。予定金額は確認時に実額へ置き換えられ、支払確認で実家計簿に記録されます。実質コストは契約の対象月へ円単位で配分し、所有物の購入費・修理費を使用月へ配分します。ローン・分割払いの元本は支出へ重複計上せず、利息を費用にします。

Widget「全画面で支出を入力」は、小・中・大のサイズで配置できます。タップするとアプリの大きなテンキー画面を直接開き、入力途中の金額・ジャンル・支払元を引き継ぎます。登録後は「続けて入力」や「取り消す」を選べます。「閉じる」で通常画面へ戻ります。登録済みの状態から開いたときは次の入力を開始します。

従来の操作はWidget一覧の「Widget内で支出を登録」で引き続き利用できます。全画面対応前のソースと署名済みアプリは `.rollback/20261027-before-fullscreen/` に保存しています。端末を元の版へ戻すには同ディレクトリの `restore-device.sh`、ソースの差分確認には `python3 restore-source.py` を使います。ソースを戻す場合は `--apply` を指定し、新しい作業は `pre-restore-*` に退避されます。端末のアプリを削除せず更新するため、家計データ自体を過去へ巻き戻す操作ではありません。

ホーム画面の大サイズWidget「Widget内で支出を登録」では、アプリを開かずにテンキーで金額を入力し、ジャンル・支払元を選んで当日の支出を登録できます。初回更新後は一度アプリを開き、既存データを共有領域へ準備してから、ホーム画面のWidget追加で「家計簿」→「Widget内で支出を登録」を選んでください。

登録直後の「取り消す」で直前の支出と口座・カードへの反映を取り消せます。「続けて入力」で金額をリセットし、ジャンル・支払元を引き継ぎます。アプリで編集・関連付けた取引は誤って消さないようWidgetからの取消を拒否します。収入・日付指定・メモ・節約可能フラグはアプリ側で扱います。複数配置したWidgetは入力内容を共有します。

Widgetの操作には端末のロック解除が必要です。共有領域の準備や保存が失敗した場合は、既存データを保持してエラーを表示します。移行前の保存領域も残し、空の家計簿へ自動的に切り替えません。アプリとWidgetには同じApp Groupの署名権限が必要です。`project.yml` の `KAKEIBO_APP_GROUP` を共通の識別子として使用します。

「契約・固定費」の「今月分をまとめて確定」では、当月の未確定サブスクリプションを件数・予定額の確認後に一括記帳できます。予定額・支払日・契約のカテゴリ・支払元を使用します。実際の送金は行いません。変動額は事前に支払予定を修正してください。処理は全件をまとめて保存し、確定済みは再記帳しません。

定額サブスクでは契約ごとに「支払日に自動確定」を設定できます（初期状態はオフ）。アプリ起動・復帰・再読込時に、当月の支払日を迎えた未確定分を予定額で記帳します。アプリ終了中の定刻実行や過去月の自動記帳は行いません。履歴には契約名付きの「管理・サブスク」などのタグを表示し、所有物の購入・売却・修理に関連付けた取引も識別できます。

「契約・固定費」は指定した支出カテゴリごとに表示します。画面上部に全体の月額換算合計、各カテゴリに小計を表示し、終了済み契約は合計から除きます。日・週・月・年の支払周期をそろえた比較用の概算で、実際の請求額や当月の支払予定額とは異なります。

新規契約で種類が「サブスクリプション」の場合は、「サービスから選ぶ」から14件の候補をカテゴリ別に選べます。入力されるのはサービス名だけです。金額・支払周期・日付・支払元は実際の契約に合わせて指定してください。入力済みの名前を別の候補へ変えるときは置き換えを確認します。「その他・手入力」から任意の名前を入力でき、候補を選んだ後も名前を編集できます。一覧から戻っても入力は消えません。候補は端末内にあるため通信なしで使えます。既存契約の編集では現在の名前をそのまま編集します。

旧 LifeCost アプリの JSON・共有ファイルを読み込む画面と自動案内はありません。移行方式は利用状況が定まった後の別課題です。以前に取り込んだ履歴・支払予定は保持し、家計簿自身の JSON バックアップには引き続き含めます。

DBはv5、JSONバックアップはv4です。v1〜v3のバックアップを読み込めます。統合データは端末内に保存し、旧App Groupの自動取込は使いません。CloudKitを構成したビルドでは新しい統合データの同期動作を別途実機で確認する必要があります。

## 入力画面のデザイン

入力画面のタイトルはコンパクトに表示します。保存ボタンはタブバー上に固定し、左右16ptの余白、高さ48pt以上、角丸12ptで表示します。テンキーは控えめなグレーで統一し、日付・メモなどの補助項目をまとめています。
