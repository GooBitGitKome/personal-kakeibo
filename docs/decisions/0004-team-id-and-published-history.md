# Team ID の扱いと、公開済みの履歴の作り直し

日付: 2026-11-28

## 背景

最初に公開した履歴（公開から 1 日足らず）に、個人を特定できる情報が含まれていた。

- Apple の Team ID（`project.yml`、`project-*.yml`、`project.pbxproj`）
- Mac のユーザー名（追跡されていた `xcuserdata` のパスと内容）
- コミットの作者の氏名とメールアドレス

## 決定

1. **Team ID**: コミットするファイルに入れない。共有設定は `Config/Signing.xcconfig`（空）、自分の値は Git に入らない `Config/Signing.local.xcconfig` に書く（[#11](https://github.com/GooBitGitKome/personal-kakeibo/issues/11)）。署名なしのビルドと CI は、Team ID なしで動く。
2. **履歴**: 旧リポジトリを削除し、同名の新リポジトリに、次を取り除いた履歴を置く。
   - 追跡されていた `xcuserdata`
   - Team ID
   - 作者とコミッターは、GitHub の ID `GooBitGitKome` と GitHub の noreply メールアドレスに統一
3. **Issue**: 新しいリポジトリに再作成し、旧番号を維持した。旧 PR #2〜#4 は再現できないため、同じ番号の完了済み Issue に記録した。
4. **タグ**: `v0.1.0` は、新しい履歴の同じ変更（`5dfca63`）に作り直した。注釈と内容は同じ。
5. **今後**: コミットは noreply のメールアドレスで行う。リポジトリのローカル設定に書いてある。

## 検討した代替案

| 案 | 採用しなかった理由 |
|---|---|
| 履歴を書き換えて force-push する | 旧コミットが GitHub の PR の参照に残り、古い SHA の URL から読める。消すには GitHub サポートへの依頼が必要 |
| 履歴は変えず、今後だけ noreply を使う | 公開済みの個人情報が残る |

## 残るもの・限界

- 旧リポジトリの削除前に取得された複製は、取り戻せない。公開から削除までに、フォークとスターはなかった。
- Team ID は秘密鍵ではない。署名の権限は証明書とプロビジョニングプロファイルが決める。
- 旧リポジトリの CI 実行の記録は失われた。[検証記録](../validation.md) の実行 ID は、旧リポジトリのもの。
