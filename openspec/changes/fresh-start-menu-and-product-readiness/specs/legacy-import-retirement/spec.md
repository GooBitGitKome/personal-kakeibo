# Spec Delta

## Purpose

利用方法が確立していない旧 LifeCost 連携の読込を現行製品から外しつつ、過去に保存された家計データを保持し、将来の移行設計を妨げないようにする。

## ADDED Requirements

### Requirement: 旧 LifeCost 読込の停止
アプリは旧 LifeCost の JSON バックアップおよび共有ファイルから新しい契約・所有物・支払予定を取り込んではならない（MUST NOT）。旧読込の選択、プレビュー、確定、自動案内を画面に表示してはならない。

#### Scenario: メニューとリマインダーを開く
- **WHEN** 利用者がメニュー、家計管理、リマインダーを開く
- **THEN** 旧 LifeCost の取込・連携履歴を操作する項目は表示されない

#### Scenario: 旧 LifeCost ファイルが端末上にある
- **WHEN** 旧 LifeCost の共有ファイルが端末上に存在してアプリが起動する
- **THEN** ファイルの読込や自動取込案内は開始されず、家計データも変更されない

### Requirement: 保存済みデータの保持
旧読込機能を停止しても、既存ストア内の取引、契約、所有物、支払予定、取込履歴を消去してはならない（MUST NOT）。更新後も保存済みの通常の家計データを読み出せなければならない。

#### Scenario: 旧取込履歴を持つストアを更新する
- **WHEN** 旧 LifeCost の取込履歴と家計データを含む既存ストアで更新版を起動する
- **THEN** データが削除されず、取引・契約・所有物・支払予定の既存値を読み出せる

### Requirement: 家計簿バックアップの維持
家計簿自身の JSON バックアップ・復元と CSV 出力は利用可能でなければならない（SHALL）。旧 LifeCost 読込の停止に伴って、既存の家計簿バックアップに含まれる保存済みデータを黙って欠落させてはならない。

#### Scenario: 旧取込履歴を含む家計簿バックアップ
- **WHEN** 旧取込履歴が保存されている家計簿から JSON バックアップを出力し、復元プレビューを行う
- **THEN** 保存済みの取込履歴を含む値が保持され、利用者の確認前にストアは変更されない

## REMOVED Requirements

### Requirement: 旧 LifeCost データの新規取込
**Reason**: 初回製品の利用方法として旧アプリ移行を確立しておらず、新規作成を入口とするため。
**Migration**: 新規データはメニューから契約・所有物・支払予定を作成する。旧アプリからの移行は、対象形式・重複判定・失敗時保護を定める後続変更で改めて提案する。既存ストア内のデータは保持する。
