# Spec Delta

## Purpose

利用者が日々の記録と状況確認を続けながら、資産・契約・口座などの管理機能へ一貫した入口から移動できるようにする。

## ADDED Requirements

### Requirement: 独立したメニュータブ
アプリは主要画面から常に選択できる独立した「メニュー」タブを提供しなければならない（SHALL）。メニューは設定画面の別名ではなく、管理機能と設定への入口を持つ画面とする。

#### Scenario: 主要画面からメニューを開く
- **WHEN** 利用者が入力、履歴、ホーム、リマインダーのいずれかを表示して「メニュー」を選ぶ
- **THEN** 管理項目と設定への入口を備えたメニュー画面が開く

### Requirement: 資産と契約の管理入口
メニューは所有物・修理費、およびサブスクリプションを含む契約・保険・固定費の管理入口を提供しなければならない（SHALL）。ホーム上の同じ管理入口と設定上の重複入口は整理しなければならない。

#### Scenario: サブスクリプションを管理する
- **WHEN** 利用者がメニューの契約管理を選ぶ
- **THEN** 既存の契約を確認し、新規契約を追加できる画面へ移動する

#### Scenario: 所有物を管理する
- **WHEN** 利用者がメニューの所有物管理を選ぶ
- **THEN** 既存の所有物を確認し、新規所有物を追加できる画面へ移動する

### Requirement: 関連管理項目と設定への移動
メニューは口座・カード、支払予定、設定への入口を提供しなければならない（SHALL）。ホームは集計・残高・期限などの状況を表示し、管理操作の主入口として機能してはならない。

#### Scenario: 口座と設定へ移動する
- **WHEN** 利用者がメニューで口座・カードまたは設定を選ぶ
- **THEN** 選択した既存の管理画面または設定画面が開き、戻る操作でメニューへ戻る

#### Scenario: ホームの状況確認
- **WHEN** 利用者がホームを開く
- **THEN** 実収支、実質コスト、支払予定、契約期限を確認でき、資産・契約の編集用入口はメニューに集約されている
