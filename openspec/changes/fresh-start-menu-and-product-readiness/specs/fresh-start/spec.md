# Spec Delta

## Purpose

旧アプリからの移行を前提にせず、初めて使う人が空の家計簿から収支、サブスクリプション、所有物の記録を始められるようにする。

## ADDED Requirements

### Requirement: 空の家計簿向け初回入口
利用者が作成した家計データがなく、初回案内を完了していない場合、アプリは新規作成を案内する入口を表示しなければならない（SHALL）。自動生成された初期カテゴリだけでは家計データありと判定してはならない。

#### Scenario: 初回起動
- **WHEN** 利用者が新規インストール後、作成済みの取引・口座・契約・所有物がない状態でアプリを開く
- **THEN** 旧アプリの取込ではなく、新規作成を選べる入口が表示される

#### Scenario: 既存データを持つ利用者
- **WHEN** 保存済みの取引・口座・契約・所有物のいずれかがある状態でアプリを開く
- **THEN** 初回案内を強制せず、通常の利用画面を表示する

### Requirement: 最初の操作の選択
初回入口は収支の記録、サブスクリプションの追加、所有物の追加、および後で始める選択を提供しなければならない（SHALL）。どの選択でも利用者の既存データを削除してはならない。

#### Scenario: 新規作成へ進む
- **WHEN** 利用者が初回入口でサブスクリプションまたは所有物の追加を選ぶ
- **THEN** 対応する新規作成画面へ進み、保存またはキャンセル後に通常の画面へ移動できる

#### Scenario: 収支から始める
- **WHEN** 利用者が初回入口で収支の記録を選ぶ
- **THEN** 金額・カテゴリ・日付を入力できる画面へ進む

#### Scenario: 後で始める
- **WHEN** 利用者が初回入口で「後で始める」を選ぶ
- **THEN** 通常の画面へ進み、次回起動時に初回入口を繰り返さない

### Requirement: 作成失敗時の保護
初回入口からの作成が保存に失敗した場合、アプリは失敗を示し、入力内容を保持して再試行できるようにしなければならない（SHALL）。

#### Scenario: 最初の契約の保存失敗
- **WHEN** 利用者が初回入口から契約を入力し、保存処理が失敗する
- **THEN** エラーが表示され、入力内容が残り、家計データは部分的に作成されない
