# Tasks

## 1. サービス名の選択と入力保護

- [x] 1.1 設計書の初期14件をカテゴリ別の同梱カタログとして定義し、新規サブスクリプションの「サービスから選ぶ」から一覧へ進めるようにする。管理・初回案内の両方で入口を確認し、他の契約種類と既存契約の編集では表示されないことをUIテストする。iPhone 12 miniで全カテゴリと「その他・手入力」へ到達でき、文字サイズを拡大しても項目を識別・選択できることを確認する。
- [x] 1.2 選択結果を名前だけへ反映し、入力済みの別名は置き換えを確認する。空欄・同名・別名の承認とキャンセル、一覧から戻る、「その他・手入力」、選択後の名前編集、種類を切り替えたときの動作をUIテストする。金額・周期・カテゴリ・開始日・最初の支払日・支払元が選択前後で一致することも確認する。
- [x] 1.3 READMEと実機確認手順に候補選択・手入力・名前の置き換えを案内する。画面文言と一致し、サービス名だけが入力されること、金額・周期は実際の契約に合わせて指定することが明記されていることを確認する。

## 2. 保存経路と統合確認

- [x] 2.1 選択した名前・手修正した名前の保存と再起動後の表示、金額未入力などのエラーと入力保持、契約追加のキャンセルをUIテストする。候補選択だけでは契約・支払予定が増えず、保存後に通常の契約として扱えることを確認する。
- [x] 2.2 候補表示に通信や外部データ取得の依存がないことを確認する。既存の保存失敗時の巻き戻し・バックアップ往復を含む `swift test`、標準プロジェクトのiOS端末向けビルド、OpenSpecの厳格検証を実行し、結果とUI確認画像を検証記録に残す。

## Workflow follow-up

- 候補の追加や名称変更は、既存契約の名前を書き換えない形で個別に行う。
- 料金・プランの自動入力や外部サービス連携は別変更として扱う。
- 本変更のレビュー後にアーカイブと主仕様への同期を行う。
