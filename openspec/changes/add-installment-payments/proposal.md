# Proposal

## Why

分割払いの購入は、現状では契約の種類「分割払い」を選び、支払確認のたびに元本と利息を自分で入力する必要がある。購入時に総額と回数を入れるだけで全回の支払予定ができ、残りの回数と残額を確認でき、取消・繰上返済も扱えるようにする（v0.2.0、Issue #5）。

## What Changes

- 新規の「分割払いを登録」を追加する。購入名、購入額（元本）、支払総額、回数、初回支払日、支払元口座、未払口座、カテゴリを入力する。購入した所有物の登録は任意とする。
- 支払総額と購入額の差を手数料・利息とし、全回の支払予定（各回の支払額と、その内訳の元本・利息）を自動生成する。端数は各回を切り捨て、余りを最終回に足す。
- 登録時に、購入額を未払口座の残高に記帳する。元本は支出へ計上しない。利息・手数料だけを、支払月の費用とする（現行の方針を維持する）。
- 支払確認では、予定の元本と利息を初期値にする。実額の変更も、利用者が選べる。
- 契約の詳細に、残り回数、残りの支払額、残りの元本を表示する。
- 取消（未払いの予定をすべて取り消す）と、一括の繰上返済（残りの元本と、任意の手数料を支払い、残りの予定を取り消す）を追加する。
- 残りの条件の変更（残りの支払総額と回数を入れ直し、未払いの予定だけを作り直す）を追加する。
- JSON バックアップを v5 にする。v1〜v4 の読み込みは維持する。

## Capabilities

### New Capabilities

- `installment-payments`: 分割払いの登録、支払予定の生成と端数処理、集計への反映、残額の表示、取消・繰上返済・条件変更。

### Modified Capabilities

なし。既存の統合家計簿の方針（元本は支出に入れず、利息を費用にする）は、新しい仕様が引き継ぐ。

## Impact

- `PersonalKakeibo/Domain`: 分割払いの計算（新規）、`FinanceRules`（検証、支払予定の生成、実質コスト）、`IntegratedFinance`（契約・支払予定・記帳の項目）。
- `PersonalKakeibo/Application`: 登録、取消、繰上返済、条件変更の処理。
- `PersonalKakeibo/Infrastructure`: `BackupFormat`（v5）。
- `PersonalKakeibo/Presentation`: 分割払いの登録画面、契約の詳細。
- `Tests/`: 端数の性質、集計、バックアップ v4 → v5、旧ストアの読み込み。
- README、CHANGELOG、`docs/validation.md`。

## 確定事項と既定値

利用者が決めた事項（2026-11-28）:

- 範囲: 登録・全回の予定の自動生成・残額の表示・取消・繰上返済
- 手数料・利息: 支払総額と回数を入力し、差額を利息・手数料とする（年率は扱わない）
- 端数: 各回は切り捨て、余りは最終回
- 集計: 現行の方針を維持する
- 保存形式: 変更し、Migration Plan と旧ストアの試験を追加する

本提案の既定値（要確認）:

- 繰上返済は一括のみとする。一部の繰上返済（期間短縮・返済額軽減）は扱わない。
- 取消は、未払いの予定だけを取り消す。記録済みの支払は残す。返金は既存の返金機能で扱う。
- カード会社の分割は、未払口座にカード口座を選ぶ形で扱う。支払元は、現状どおり銀行・現金の口座とする。
- 年率からの計算、ボーナス払い（v0.3.0）、一部繰上返済は対象外とする。
